# Mnema 商業策略討論紀錄

> 基準日:2026-07-12。本文整理一次完整的商業化討論 + 一份深度研究驗證報告(105 個代理、23 個來源、25 條主張經三票對抗式查證)。
> 性質:策略討論紀錄與方向選項,**不是已批准的計畫**。時效敏感段落(OpenAI 功能、麻布流失潮)半年後須重驗。

## 1. 定位結論

### 1.1 核心論點

- 賣點不是「六合一 life OS」——每個 Space 單獨都打不贏該垂直的王者(Anki/Todoist/YNAB/Wanderlog),all-in-one 的心智空間被 Notion 佔走。
- 也不再是「AI 可寫入」本身——OpenAI 已親自下場(ChatGPT Health 2026-01、Finances 2026-05/06,見 §3.2),這個抽象賣點正在被平台吸收。
- **可防禦的定位:「台灣在地資料進水口 × 結構化生活資料庫 × AI 放大器」。** ChatGPT Finances 走 Plaid(不含台灣銀行)、Health 限美國病歷網絡;台灣的電子發票、LINE、在地業者確認信,大廠永遠不會做。AI 是放大器,不是主賣點。
- 長期資產(空窗期關閉後還剩下的):(a) 使用者累積的結構化、可匯出、自有的資料——「system of record」位置;(b) 在地資料掛鉤。介面層(chat、copy-paste、connector)都會被平台吸收,資料層不會。

### 1.2 目標客群(修正過程)

1. ~~會用 MCP 的人~~ → 太小,且已有自己的工具鏈。MCP 保留為免費副產品(OAuth 做完後 connector 底層就是它),不投行銷資源;此人群的價值是擴音(部落格/教學影片),不是轉換。
2. **「只會用 chatbot 的人」是原始初衷與正確主市場**——台灣付費 ChatGPT/Claude 用戶是十萬級。痛點一句話:「跟 AI 聊了半天,什麼都沒留下來」。
3. 產品哲學(owner 原話):「現在的一切工具都不夠懶,我完全不想自己做任何操作,只想告訴 AI 幫我做。這個工具是適應現有環境的折衷辦法。」——注意「折衷辦法」有保存期限,見 §3 空窗期分析。

### 1.3 三層接入模型(owner 提出)

| 層 | 對象 | 內容 | 定位修正後的評價 |
|---|---|---|---|
| 1. Copy-paste bridge | 所有人 | mnema 提供 prompt 模板 → 用戶貼到任何 chatbot → 產出固定 JSON → 貼回 mnema(Zod 驗證 + bulk RPC 匯入,零推論成本) | **好的行銷素材+冷啟動解法,不是日常工作流**。批次建立(行程/字卡)可行;日常記錄(記帳)會死在往返摩擦。定位=漏斗與第一次啟用,不是留存來源 |
| 2. OAuth connector / MCP | 付費 chatbot 用戶 / 專業者 | claude.ai custom connector、ChatGPT apps(底層皆 MCP)。連接由 chatbot 側發起 → 跳轉 mnema 授權頁 → 完成 | **商業化的閘門**。工程硬前提 = Phase 3b(OAuth 2.1 + PKCE + DCR)。終局是上官方目錄(一鍵連接),需送審 |
| 3. 內建 AI(付費) | 大眾 | mnema 代管 AI,app 內直接完成一切 | 對的終局,但這層全世界都在打,無優勢;經濟結構改變(要精算 token 毛利)。留為付費 tier,靠 §1.1 的兩個資產差異化。LINE bot 屬此層,先不做 |

**短影片原則:一支影片一條路徑、一個場景、一個 magic moment。** 三層是定價頁結構,不是鉤子。拍三支(行程/記帳/字卡)各展示一條路,用數據選場景再壓注。

## 2. 深度研究驗證報告摘要(2026-07-12)

四個子題,22 條主張通過對抗式驗證。完整輸出與來源清單見討論紀錄;以下為承重結論。

### 2.1 Dot(New Computer)覆盤 —— 同賽道的屍體

- 2025-09-05 宣布關閉(官方說法:創辦人願景分歧,非承認商業失敗)。
- **官方宣稱「數十萬用戶」;Appfigures 實測 iOS 終身下載僅約 24,500 次**,無 Android 版。(TechCrunch, 3-0)
- 教訓:(1) 純「AI 陪伴/記憶」缺乏可留存的結構化價值——mnema 以資料層為本體、AI 為寫入方,正好是 Dot 缺的錨點;(2) 「AI 幫你管理人生」抽象賣點本身不帶流量;(3) 官方用戶數不可信,驗證假設用第三方數據;(4) 先募資後找市場的死法。
- 覆蓋缺口:Martin/Friday/Mem 存活狀態未通過驗證,競品地圖僅 Dot 一案。

### 2.2 平台侵蝕:空窗期評估

- ChatGPT 記憶:2024-09 全層開放基本版;2025-04 全對話記憶鎖付費層。至今仍是**非結構化**偏好層,且 OpenAI 把深度記憶當變現槓桿——佐證「結構化資料值得付費」。
- ChatGPT 排程任務:2026-06 升為一級功能(側欄 Scheduled、監控型任務)。**單純提醒功能不再是護城河**,Tempo 的差異必須來自「任務連結帳本/行程/健康」的結構。
- **ChatGPT Health(2026-01)與 Finances(2026-05/06,Plaid、僅美國)已是結構化生活資料垂直空間**——但皆不覆蓋台灣,Plaid 不含台灣銀行,不碰電子發票。空窗期:全球 12–24 個月內逐域被填;**台灣在地資料源的空窗明顯更長**。
- **Apps SDK 標準化於 MCP,且明文「Bring your own backend」——平台不做資料持久化,把資料層讓給第三方。** mnema 押 MCP 押對;風險是 ChatGPT 也能寫入 Notion 等既有工具形成替代。
- 工程缺口(雙平台一致):connector 要求 OAuth,現行靜態 `mk_` key 不符 → **Phase 3b 是硬前提**;上公開目錄需送審。

### 2.3 電子發票 API:技術可行,合規是門檻

- `carrierInvChk`(發票清單)+ `carrierInvDetail`(**品項級明細**:品名/數量/單價/金額)完整支撐自動記帳與食材場景。查詢區間須同月份;品名品質取決於賣方上傳。(財政部規格書 v1.9/v2.0 逐字驗證, 3-0)
- 申請門檻:公司主體(個人 2024 後不受理)、**ISO27001/CNS27001 認證(取證+年審數十萬 NT$ 起,2025 起實際執行)**、審核有裁量、授權 3 年一換。
- 資料條款:原始發票**暫存不得超過該期領獎期限**;範圍外利用須重新同意且**每半年續一次**;軌跡保存六個月。→ 合規做法:在同意下即時轉化為使用者自己的 Galleon 交易/Kitchen 食材(使用者自建資料不受此限),同意流程設計成半年可續的 UX。所有競品受同樣約束。
- **策略結論(2026-07-12 修正):紙本 QR 掃描方案否決**——掃描不懶(比手動記帳多動作)、用紙本發票者非 TA;雲端載具覆蓋率已高,**只有雲端發票自動同步成立**。而自動同步沒有便宜的路(載具 API 是唯一合法管道;以用戶帳密爬財政部網站違反條款且脆弱,禁走)。→ 發票進水口從「便宜的第一步」改為**「驗證需求後才投的資本決策」**(公司主體 + ISO27001 數十萬 NT$);投下後反成擋 indie 的護城河。需求驗證改用:fake-door 測試(app 內放「自動同步雲端發票」假開關,量點擊率與留 email 意願)+ 無合規門檻的進水口先行(信件轉寄、LINE)。

### 2.4 定價與可達性

- **麻布記帳 2026-04-01 全面收費**(免費用戶連手動記帳都不能用):早鳥 NT$69/月,6 月起 **NT$149/月**,2027 年費 NT$1,499。→ (a) 台灣定價錨點 NT$69–149/月;(b) 麻布砍免費層因銀行連線有每用戶邊際成本——**mnema 免費層零推論成本正好迴避此死穴**,結構性差異;(c) **一波對 NT$149 不滿的流失用戶正在找替代品——有時效的獲客窗口**。
- 漏斗算術(RevenueCat, 3-0):freemium 下載→付費 D35 中位轉換率 **2.18%** → 2,000–3,000 付費用戶需 **9–14 萬下載**。無在地鉤子達不到(Dot 全球僅 2.4 萬);有「發票+對獎」級鉤子屬有挑戰但可達。頂尖四分位轉換率有下修空間。
- 邊界:麻布是唯一驗證過的定價錨點;RevenueCat 樣本偏英語市場;三條被否決主張勿引用(ChatGPT 記憶時間軸細節、發票 API HMAC 簽章細節、亞太每安裝營收 $0.35)。

### 2.5 競品補充(2026-07-13 網路查證)

- **「發票 + AI」組件全部有前例**:MOZE 已做發票掃描 + ChatGPT 品項自動分類 + 自動對獎(doc.moze.app/feature/invoice);麻布做自動同步;**LINE 聊天式 AI 記帳已存在**(「記帳小旺來」wanglai.tw,LINE 內一句話記帳)——第三層的 LINE bot 假設有人在跑,須實測研究其定價/留存。尚無人做的:用戶自己的 AI **讀寫**全部生活資料(競品皆單向進、不可對話查詢)、發票明細→食材過期(跨 Space)、帳+行程+任務同庫串連。主敘事微調:強調「不用掃(雲端自動進)+ 你的 AI 答得出錢花去哪 + 食材過期提醒」,避開 MOZE 已佔的「掃發票 AI 分類」。
- **Copy-paste prompt 模式在 Anki 生態是成熟大眾工作流**(200 條 prompt 庫、醫學生教學氾濫)——需求已被驗證、現有流程痛點明確(CSV 格式/欄位對映/編碼)。差異化=包到無痛:場景化 prompt 一鍵複製、Zod 驗證+預覽、繁中、跨場景(不只字卡)。定位一句話:「Anki 那套流程,不用格式、不只讀書、全中文」。此發現支持學習影片第一支拍(觀眾已有明確意圖)。
- **命名決議**:Mnema 留作品牌傘(發音「聽一次拼不出來」,過不了口碑傳播測試;台灣市場需中文行銷名,影片/商店以中文名為主)——中文名待定,勿陷命名迴圈。

## 3. 進水口(data inlets)地圖

「懶」的承諾=資料自己流進來。三條管線涵蓋台灣生活資料大宗;每條管線 N 個解析器,邊際成本遞減。

| 優先 | 進水口 | 說明 | 門檻 |
|---|---|---|---|
| P0 | **信件轉寄進水口**(TripIt 模式) | 每用戶專屬地址 `u_xxx@in.mnema.app`;訂房/機票確認信多含 schema.org 標記可規則解析。在地解析包:高鐵/台鐵/KKday/Klook/agoda;副產品:外送(foodpanda/UberEats)、電商(蝦皮/momo)訂單、信用卡帳單信 | 收信基建;**勿走 Gmail API**(`gmail.readonly` 是 restricted scope,須年度 CASA 稽核,indie 不划算) |
| P0 | **LINE 分享捕捉** | 非 AI bot,只做「分享到 mnema 官方帳號 → captures inbox」;進台灣人的分享肌肉記憶 | LINE OA 費用,開發量小 |
| P1(資本決策) | **雲端發票載具 API**(`carrierInvChk`/`carrierInvDetail`) | 品項級明細 → Galleon 交易 + Kitchen 食材過期提醒 + 對獎。**唯一成立的發票形態**(紙本 QR 掃描已否決:不懶、非 TA);先以 fake-door 驗證需求強度,數字達標才投 | 公司主體 + ISO27001(數十萬 NT$)+ 資料條款 UX;投後成為對 indie 的護城河 |
| P2 | Google 日曆 / .ics、Google Maps 收藏匯入、Apple Health/Google Fit | 通用組 | 低 |
| P3 | 健康存摺(健保快易通) | 用藥/檢查 → Health;在地程度滿分 | SDK 偏機構授權,待查證 |
| — | 銀行/信用卡 | 台灣 open banking 弱;帳單信轉寄解析為替代 | 併入轉寄管線 |

備註:Gmail → AI → mnema **不需要 MCP**——轉寄進水口(推薦)、server 端 Gmail API(CASA 稽核,不推)、用戶自己的 AI 當中介(connector 彩蛋)三條路,最大眾的那條連長輩都會操作。

## 4. 延伸方向(依與現有架構的距離排序)

1. **更多進水口**(§3)——發票只是第一個,每條都加深「懶」與黏性。
2. **語音捕捉**——widget 長按說一句 → captures inbox → AI 分流成任務/帳/筆記。「懶到底」哲學的最短實現;captures 表與 Capture FAB 已存在。
3. **共享成長迴圈**——旅遊創作者發布可 clone 的行程(獲客素材);情侶/家庭共享帳本 → 家庭方案(付費意願高、流失低)。ledger members、share link 皆現成。
4. **Study B2B 支線**——補習班/家教建牌組、學生訂閱複習;付費方是機構,客單價不同。遠期。
5. **定位延伸:「比任何 chatbot 都長壽的記憶層」**——chatbot 會換,人生資料庫只有一個;Dot 用戶「記憶陪葬」的反面敘事。
6. **AI 整理暫存(capture 自動分流)——第三層的正確第一步(定案:要做)。** captures inbox 加 AI 分流:隨手記 → 小模型(Haiku 級,一則<NT$0.01)分類成任務/帳/筆記的**提議**,用戶確認後走同一條 RPC(`created_via` 溯源不變)。免費層配額(如 30 則/月)、付費層無限——不破壞零推論經濟學,反而給免費→付費一個具體升級理由;也是第一、二層用戶在 app 內體驗 AI 的唯一機會。
7. **「目標 → AI 建好整套流程」(寵物點藥 q3mo、換濾芯 q6mo)——不是 feature,是行銷素材。** `create_tasks_bulk`+`set_recurrence`+`add_reminder` 全是現成工具,connector 用戶今天就能用;單純週期提醒是 todo app commodity,非護城河。正確用法=demo 影片題材(「告訴 AI 你養了貓」)。與第 6 點是**同一個引擎**(自然語言→結構化提議→確認→RPC),capture 分流是第一個皮、routine 建立是第二個皮。

### 客製化問題的結論(owner:「非常簡單的框架+非常彈性的自訂欄位,TA=懶得比較 app、懶得排行程的一般用戶」)

- 先指出的矛盾:**懶得比較 app 的人,更懶得自訂欄位**——欄位編輯器是 Notion 玩家的樂趣、懶人的負擔。懶人要「好的預設+直接給結果」。
- **定案的解法:自訂欄位是給 AI 用的,不是給用戶用的。** 用戶對 chatbot 說「排京都行程,每天要有預算上限和訂位狀態」→ AI 透過 API 在該行程上動態建立型別化欄位並填值。核心 schema 固定(AI 寫入依然可靠)+ 受約束的 key-value 擴充(由 AI 代理操作)+ UI 通用渲染——用戶永遠不碰表單編輯器,但每個人的行程長得不一樣。此功能本身即「懶到底」哲學的展示品。
- 輔助手段:(a) **隱藏而非自建**——模組化 UI,Space/區塊/欄位可關(推廣既有 per-user layout 機制);(b) 遠期:**AI 生成視圖**——資料層固定、呈現層由 AI 客製。
- Obsidian 的啟示:把進階客製外包給**插件/模板生態**,核心保持結構化。

### 「可匯出=沒黏性」的反駁(定案)

黏性(retention)≠綁架(lock-in)。Obsidian 以「資料隨時整包帶走」為賣點卻有最狂熱的留存;扣資料的產品死時用戶直接棄資料走人。真黏性=累積的結構化資料(匯出的 JSON 無處還原 SRS 排程)+接好的水管(OAuth/發票同步/家人)+其他人(共享帳本成員匯不走)。對 mnema,可匯出是**信任入場券**:越容易離開→越敢存→存越多→越不離開。真正該擔心的是「還沒累積到值得留下的資料就流失」——onboarding 問題。

### 5.1 Venture 的真實代價(給創業小白的白話版)

VC 基金靠極少數 100× 案子撐回報,故投後唯一符合投資人利益的路徑是「不計代價衝大,或快死騰位」——**穩定賺錢的小生意對 VC 是失敗**。具體代價:全職(無邊上班邊做)、僱人管人(從寫 code 變開會)、逐輪稀釋(終局常剩 10–20%)、董事會可換掉創辦人、股票出場前是紙(中位七至十年,期間收入常低於工程師薪水)。Indie/bootstrap 則保留一切選擇權。**預設走 indie;venture 是數據爆了且確定想過那種生活時才做的決定。**

### 5.2 抄襲風險與護城河(「做起來很快,會不會馬上被抄?」)

前提正確:code 不是護城河。但要問「誰、為什麼抄」:

- **大廠不會抄**——台灣電子發票 TAM 對 OpenAI/Notion 是 rounding error;大廠的忽視是小市場的保護傘。
- **最該防的是麻布記帳加 AI 層**(有 ISO27001、有用戶、有發票管道);但它有每用戶銀行連線邊際成本、老 codebase、記帳公司的組織慣性——窗口以年計,非永遠。
- **其他 indie**——低技術護城河 ≠ 零工作量(40 migrations、158 tools、OAuth、雙語、合規,照抄也是數月)。

Code 以外可累積的護城河:用戶存入的結構化資料(抄得走 app、抄不走兩年的帳)、ISO27001+API 授權(執照)、共享關係(帳本成員)、信任/品牌(BYO-AI、資料自主敘事)、**分發**(影片、KOL 關係、麻布流失潮卡位——最被低估的一項)。檢驗標準:**會因被抄而死的不是生意,是 feature。** All-in-one 本身無護城河,但本計畫賣的不是 all-in-one,是「在地資料自動流入 + AI 處理」,Space 只是容器。Indie 的期望值算術寬容:最壞情況=業餘時間換到自用工具+作品集。
